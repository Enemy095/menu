# BE-001/MOD-001 — Spring Boot scaffold and module boundaries

Status: `ready`  
Wave: 1  
Dependencies: `PLAN-001`

## Objective

Создать воспроизводимый Java 25/Spring Boot backend skeleton в `apps/api` и сразу зафиксировать Spring Modulith boundaries. Результат должен компилироваться, тестироваться и собирать `bootJar`, но не реализовывать database schema или business endpoints.

## Exclusive ownership

Агент единолично владеет:

- `settings.gradle.kts`;
- `build.gradle.kts` и `gradle.properties`, если нужны;
- `gradle/**`, `gradlew`, `gradlew.bat`;
- `apps/api/**`, кроме будущих Flyway migrations.

Не изменять:

- `AGENTS.md`;
- `packages/api-contract/**`;
- `infra/**`;
- `docs/migration/**`;
- `Электронное меню/**`.

## Fixed decisions

- Java toolchain 25.
- Spring Boot 4.1.x stable.
- Gradle Kotlin DSL и Wrapper; не полагаться на global Gradle.
- Spring MVC, не WebFlux.
- Spring Data JPA/PostgreSQL/Flyway; H2 запрещён.
- Spring Modulith 2.1.x compatible release.
- Base package: `com.salamu.menu`.
- Modules: `tenancy`, `restaurant`, `menu`, `ordering`, `notification`, `identity`.
- Один deployable; worker позже включается property `app.worker.enabled`.

## Deliverables

- Root Gradle multi-project build с `:apps:api`.
- Version catalog с централизованными versions/libraries.
- Dependencies: web MVC, validation, Data JPA, Security, Flyway PostgreSQL support, PostgreSQL driver, Actuator, Micrometer/OTel, Spring Modulith core/test/insight, JUnit и Testcontainers.
- Minimal `MenuPlatformApplication`.
- Profiles/config: base, `local`, `test`, `production`.
- `spring.jpa.open-in-view=false`.
- Schema generation disabled/validate-oriented; никаких auto-created tables.
- UTC defaults для JVM/Jackson/Hibernate where applicable.
- Typed `@ConfigurationProperties` для platform hosts, trusted forwarding, worker enablement и mandatory external configuration; без secrets/default production credentials.
- Module packages с `package-info.java`/annotations и минимальными public API markers.
- `ApplicationModules.of(MenuPlatformApplication.class).verify()` test.
- Context smoke test, не требующий H2. Допустимо отключить datasource-dependent auto-configuration только в узком unit/module test, но integration tests позже используют PostgreSQL Testcontainers.
- Management exposure по умолчанию ограничено health/info; env/configprops не публикуются.

## Implementation sequence

1. Создать root Gradle settings, catalog и Wrapper.
2. Создать `apps/api` build и source layout.
3. Добавить application/configuration skeleton.
4. Добавить module declarations и public/internal package boundaries.
5. Добавить Modulith verification и minimal context tests.
6. Запустить Gradle check и bootJar из clean state.

## Non-goals

- Flyway SQL и JPA entities.
- Controllers или OpenAPI DTO.
- Tenant resolver.
- Security filter chain beyond safe default configuration required for context startup.
- Dockerfile, CI workflow, Redis, broker, virtual threads.

## Acceptance

- `./gradlew :apps:api:check` проходит.
- `./gradlew :apps:api:bootJar` проходит.
- Java compilation использует toolchain 25.
- Modulith verification подтверждает отсутствие cycles и illegal internal imports.
- В dependencies отсутствуют WebFlux, R2DBC, H2, Redis и Kafka.
- В build/resources отсутствуют реальные credentials.
- `git diff --check` проходит.
