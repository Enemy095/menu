# DB-001 — Flyway schema and JPA persistence baseline

Status: `superseded`
Wave: 2  
Dependencies: `BE-001/MOD-001`, `INF-001`

## Objective

Создать tenant-safe PostgreSQL schema V1–V4, JPA persistence mappings и migration tests. Database constraints должны физически препятствовать cross-tenant links; Hibernate не создаёт schema.

## Ownership

- `apps/api/src/main/resources/db/migration/**`;
- persistence entities/repositories и их tests внутри module `internal/infrastructure`;
- database-specific test fixtures, не production tenant data.

Initial migration files имеет право менять только этот agent до integration checkpoint.

## Schema

### V1 — tenancy and restaurants

- `tenants`: UUID PK, unique slug, status, locale, currency, timezone, timestamps.
- `tenant_domains`: tenant FK, normalized globally unique hostname, type, status, canonical, verified timestamp.
- `tenant_branding`: one-to-one tenant, explicit primary fields + JSONB design tokens/localized texts/hero.
- `tenant_profiles`: public contacts/address/hours/location/social links.
- `tenant_features`: `(tenant_id, feature_key)`, enabled + typed/config JSONB.
- `restaurants`: tenant-scoped UUID/slug/status/default flag.
- `tenant_order_counters`: locked per-tenant sequence allocation.

### V2 — versioned menu

- `menu_versions`: tenant/restaurant/version, DRAFT/PUBLISHED/ARCHIVED, one current published version.
- `menu_categories`: version-specific stable public ID, order, availability.
- `menu_items`: version-specific immutable snapshot, stable public ID, category, price minor, currency, image reference, availability, order.
- Composite tenant-aware foreign keys.

### V3 — orders

- `orders`: tenant/restaurant, per-tenant number, idempotency key/hash, status/type/channel, customer snapshot, comments/guest count, totals/currency, client/server timestamps/menu version/confirmation flag.
- Unique `(tenant_id,idempotency_key)` и `(tenant_id,order_number)`.
- `order_items`: item/name/price/modifier snapshots, quantity/line total.
- `order_status_history`.

### V4 — assets, destinations and outbox

- `tenant_assets`: immutable key, type, size, sha256, status.
- `notification_destinations`: channel/status/display metadata/secret reference; raw secret запрещён.
- `outbox_events`: aggregate/event/schema/payload, processing state, attempts и lease timestamps.
- `notification_deliveries`: event/destination/provider audit.

## Rules

- IDs UUID; timestamps `timestamptz`; money `bigint` minor units.
- Mutable codes lowercase with checks.
- Production Flyway files не содержат Stambul/Adamas fixtures и manager phones.
- Applied migration не редактируется после release.
- JPA entities не выходят из infrastructure package.
- OSIV disabled; schema generation disabled; Hibernate validates mappings.
- Hot-path indexes: tenant status/domain, current menu, order created/status, outbox status/available time.

## Tests and acceptance

- Testcontainers PostgreSQL 17 migration from empty DB.
- Sequential upgrade validation after every version.
- Hibernate mapping validation.
- Cross-tenant FK attempts fail at DB level.
- Unique idempotency/order number/current published menu constraints tested.
- `./gradlew :apps:api:check` passes.
- Flyway `validate` passes; `git diff --check` passes.

## Non-goals

Business seed/import, public controllers, RLS, Redis, data retention jobs.
