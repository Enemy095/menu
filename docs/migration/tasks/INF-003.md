# INF-003 - Versioned local content bootstrap

Status: done. Dependencies: INF-002 and the existing single-client schema/public API.

## Objective and non-goals

Preserve the current public restaurant configuration, menu and image bytes in Git,
and initialize them automatically on a new local Docker installation. This task
does not copy customer/operational records, credentials or notification destinations;
change production provisioning; change persistence technology; or restore raw
historical sources.

## Ownership and interfaces

- `infra/local/bootstrap/**`: immutable v1 content, integrity inventory and transaction guards.
- `infra/docker/bootstrap.Dockerfile`: local PostgreSQL/mc initializer image.
- `scripts/export-local-bootstrap.ps1`: explicit public-table allowlist and versioned export.
- `scripts/test-local-bootstrap.ps1`: disposable full-stack acceptance.
- `compose.yaml`: bootstrap completion gates frontend startup after API/Flyway readiness.
- `.gitattributes`: canonical LF for checksummed text, binary image preservation.
- `.env.example`, `scripts/start-docker.ps1`, local guide and task registry: operator integration.

The runtime API, generated client, historical Flyway migrations and application
business logic are unchanged. SQL business content lives outside production Flyway.

## Implementation and failure handling

1. Export the existing public-content tables and their asset-catalog objects.
2. Inventory frontend public files and capture the expected public API responses.
3. Check all stored bytes; retain the original IDs, public values and menu version.
4. After schema readiness, verify checksums and skip any populated application database.
5. For empty databases, copy only missing object hashes, reject conflicting bytes,
   and publish rows in one transaction with an advisory-lock/recheck.
6. Keep existing local content and operator settings untouched on every later run.

Source content must remain stable while exporting. Snapshot v1 is tied to Flyway
V9. Future schema/content revisions require a reviewed new snapshot and explicit
active-version update; they are never silently applied over local edits.

  normalizing only the local object-storage origin; frontend returned HTTP 200.
- Verified every selected table's row count and every downloaded image/font hash.
- Confirmed orders, destinations and outbox were empty on the new installation.
- Rejected a tampered snapshot, a conflicting object hash and an incompatible schema;
  each failure published no content rows. Existing conflicting bytes were not overwritten.

- Removed the isolated test containers/volumes; the normal project remained available.
- PowerShell syntax, runtime architecture guard and `git diff --check` passed.

## Handoff

The Windows entry point remains `start-docker.cmd`. New local installations now
receive the bundled public content automatically. Existing databases return
`LOCAL_BOOTSTRAP_SKIPPED`. No new release acceptance or production cutover claim
is implied; all task files must still be committed/pushed to reach GitHub users.
