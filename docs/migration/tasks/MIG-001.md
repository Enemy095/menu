# MIG-001 — deterministic legacy import

Status: `superseded`
Wave: 4  
Dependencies: `DB-001`, `CFG-001`, `MENU-001`, `AST-001`

## Objective

Импортировать Stambul и Adamas из legacy JavaScript/assets детерминированно, повторяемо и без business fixtures в production Flyway migrations.

## Mapping

- Два ACTIVE tenant: `stambul`, `adamas`.
- Один default restaurant на tenant.
- Locale `ru-RU`, currency `RUB`.
- Timezone временно `Europe/Moscow`; production promotion блокируется до подтверждения владельцем.
- Menu version 1, stable legacy item IDs и source ordering сохраняются.
- Price преобразуется `rubles × 100` в minor units.
- Stambul 23 items; Adamas 19 items.
- `deliveryBlocks=true` только для Adamas.
- Zero coordinates преобразуются в absent location.
- Public phone и private notification destination разделены.
- Private manager destination не читается importer и не хранится в manifest/fixture;
  notification module получает только заранее созданную opaque secret reference.
- Custom domain не активируется без ownership verification.
- Logos/hero импортируются через AST adapter.

## Deliverables

- Versioned import manifest и checksums.
- Import command/script внутри backend tooling.
- `--dry-run` report без PII/secret exposure.
- Idempotency по tenant slug + menu version + asset hash.
- Mapping validation report с counts, names, order, prices, features и missing fields.
- Staging-only method of destination secret injection; secret не хранится в Git.

## Execution slices

- Phase A preflight — завершён: immutable manifest, sanitized fixture, mapping inventory,
  acceptance/report и воспроизводимый verifier находятся в `docs/migration/import/`.
- `MIG-001A` — provisioning/inspection/cleanup ports, Flyway V5 ledger и provenance.
- `MIG-001B` — strict parser, canonical plan и zero-write dry-run CLI.
- `MIG-001C` — staged apply, atomic two-tenant activation, gated verification и recovery.

Архитектурные правила Phase B зафиксированы в accepted ADR-0002. Production promotion
остаётся отдельным blocked состоянием и не следует автоматически из завершения кода.

## Tests and acceptance

- Fresh import создаёт ровно два tenants и 42 items.
- Второй import создаёт нулевой diff.
- Category/item order и prices совпадают с legacy.
- Public endpoints не раскрывают destinations/secrets.
- Corrupt/duplicate/missing source data приводит к fail-fast report, не partial import.
- Production checklist требует confirmed timezone, contacts, domains и notification destinations.
