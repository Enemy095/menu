# ORD-001 — transactional ordering and idempotency

Status: `superseded`
Wave: 7  
Dependencies: `API-001`, `TEN-001`, `CFG-001`, `MENU-001`, `DB-001`, `SEC-001`

## Objective

Реализовать `POST /api/v1/public/{tenantSlug}/orders` как tenant-safe transactional use case с server-side pricing, snapshots, idempotency и outbox event.

## Domain rules

- Tenant active, orders feature enabled, restaurant available.
- Order type enabled for tenant.
- Name/phone/address/comment/guest count satisfy tenant limits.
- Delivery requires address; phone normalized to E.164.
- Item IDs exist in current published menu, available and belong to tenant.
- Quantity positive, per-item ≤ max, total ≤ max.
- `clientMenuVersion` equals current version or `409 MENU_CHANGED`.
- Server computes all prices/totals from menu snapshots.
- Wrong client total → `409 TOTAL_MISMATCH`.
- Unavailable item → `409 ITEM_UNAVAILABLE`.
- Future client time > 5 min → validation error; old request beyond tenant confirmation threshold sets `needsConfirmation`.

## Idempotency

- Header key length/format bounded; body key absent.
- Canonical normalized JSON includes all semantic fields including original `clientCreatedAt`, items sorted by ID.
- SHA-256 canonical hash.
- Unique `(tenant_id,idempotency_key)` is final concurrency arbiter.
- Same key/hash returns original business response including server timestamp/order number.
- Same key/different hash → `409 IDEMPOTENCY_CONFLICT`.
- Unique-race loser rolls back and rereads committed order in new transaction.

## Transaction

В одной transaction:

- allocate per-tenant order number;
- insert order;
- insert immutable item snapshots;
- insert status history;
- insert `OrderPlacedV1` outbox event.

Никакие external calls до commit не выполняются.

## Tests and acceptance

- Pure domain policy unit tests.
- Integration tests all order types/limits/error codes.
- Cross-tenant item IDs rejected.
- Concurrent duplicate creates exactly one order/outbox event.
- Same key/different payload conflict.
- Forced failure rolls back all rows/counter behavior safely.
- Backend ignores client names/prices derived from items.
- Response/error validates OpenAPI; PII absent from logs.
- Gradle check passes.
