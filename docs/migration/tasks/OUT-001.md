# OUT-001 — transactional outbox worker

Status: `planned`  
Wave: 7  
Dependencies: `ORD-001`, `DB-001`; asset dependency only if a notification embeds assets

## Objective

Доставлять tenant-specific order notifications durable at-least-once после commit, не задерживая и не отменяя order creation.

## Deliverables

- `OrderPlacedV1` payload with tenantId/orderId/schema/trace context, without destination secrets.
- Poller with bounded batch and `FOR UPDATE SKIP LOCKED`.
- Configurable concurrency, lease timeout, worker ID and graceful shutdown.
- Stale lease recovery.
- Retry: `min(5s * 2^(attempt-1), 15m)` + bounded jitter, max 10 attempts.
- Destination resolved server-side by tenant/channel.
- Notification delivery audit with provider message ID when available.
- Provider idempotency key when supported.
- WhatsApp adapter/provider boundary; client redirect is not used for real order.
- `app.worker.enabled` process-role property.
- Metrics: backlog, oldest age, attempts, success/failure.
- Redacted errors; message/phone/secrets not logged.

## Failure semantics

- Order remains successful if delivery fails.
- Outbox promises at-least-once, not exactly-once.
- Permanent/max-attempt failure becomes FAILED/dead-letter state and is operator-visible.
- Crash after external success but before DB mark may retry; provider idempotency mitigates duplicate.

## Tests and acceptance

- Crash/restart after order commit does not lose event.
- Concurrent workers claim one event per attempt.
- Transient errors retry with bounded schedule.
- Stale lease recovered.
- Permanent error reaches FAILED without altering order.
- Graceful shutdown stops claiming and completes/releases bounded work.
- PII redaction and metrics verified.
