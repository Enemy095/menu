# SEC-001 — security boundaries and rate limiting

Status: `done`
Wave: 3  
Dependencies: `BE-001`, `TEN-001`

## Objective

Открыть только три public v1 endpoint, закрыть все остальные routes и защитить order creation tenant-aware rate limiting без Redis.

## Deliverables

- Public GET config/menu и POST orders anonymous.
- Unspecified API routes denied.
- Tenant-admin/platform-admin namespaces reserved and denied until authentication tasks exist.
- Actuator на internal management boundary; наружу только явно разрешённые health/info/prometheus.
- Same-origin CORS default; explicit allowlist only.
- Per-instance Bucket4j+Caffeine limiter:
  - tenant + trusted client IP: 5/min, burst 10;
  - tenant aggregate: 120/min, burst 240;
  - все значения configurable.
- `429 RATE_LIMITED` + `Retry-After`.
- Trusted client IP только из configured ingress; direct profile игнорирует spoofed forwarded headers.
- Production note: edge distributed limiting обязателен для multiple instances; Redis требует отдельный ADR.

## Tests and acceptance

- Public GET остаётся доступным.
- Excess order POST получает 429.
- Spoofed host/IP не обходит limiter.
- Admin/unknown routes не становятся public.
- Custom-domain CORS/cookie assumptions документированы.
- Secrets/PII не логируются.
- Security integration tests, Gradle check и `git diff --check` проходят.
