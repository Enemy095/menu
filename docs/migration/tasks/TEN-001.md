# TEN-001 — trusted tenant resolver and context

Status: `planned`  
Wave: 3  
Dependencies: `DB-001`, `MOD-001`

## Objective

Реализовать единственную trusted boundary, которая преобразует effective host и optional path slug в immutable internal tenant context.

## Ownership

Модуль `tenancy` и tenant-related MVC integration/tests. Не менять schema/OpenAPI/другие business modules.

## Resolution algorithm

1. Lowercase host, удалить port/trailing dot, преобразовать IDN to ASCII и отклонить invalid hostname.
2. Forwarded headers использовать только в trusted-ingress profile/configuration.
3. Active verified custom/platform domain разрешается через repository.
4. Для configured platform/local host разрешить tenant через path slug.
5. Одновременно определённые host и slug обязаны указывать на один tenant.
6. Unknown, pending, disabled domain и inactive tenant → `404 TENANT_NOT_FOUND`.
7. Никакой query/header/body `tenantId` не меняет результат.

## Deliverables

- Value types `TenantId`, `TenantContext`, `TenantResolution`.
- Repository ports и JPA query adapters по domain/slug.
- Servlet filter/interceptor и MVC argument resolver.
- Request attribute допустим; global/static ThreadLocal как source of truth запрещён.
- MDC enrichment только для observability и гарантированная очистка в `finally`.
- Typed config: platform hosts, local aliases, trusted forwarding.
- Controlled exception → common error envelope.

## Tests

- platform path, subdomain, custom domain и localhost mapping;
- IDN/case/port/trailing dot normalization;
- host/slug mismatch;
- unknown/pending/disabled/inactive cases;
- spoofed forwarded header in direct profile;
- query/body override attempts;
- thread reuse и exception path не протекают tenant context;
- tenant A repository result никогда не возвращает tenant B.

## Acceptance

Integration suite проходит на PostgreSQL; production не имеет default tenant fallback; resolver не раскрывает internal `tenantId` в public response; Modulith verification и Gradle check зелёные.
