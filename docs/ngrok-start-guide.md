# Публичная ссылка через ngrok на Windows

Запустите **`start-ngrok.cmd`** двойным щелчком из корня проекта. Он использует
ngrok из PATH, открывает HTTPS-туннель к frontend, запускает Docker Desktop при
необходимости, собирает изменившиеся слои и поднимает приложение. После проверки
сайта и расписания через внешний адрес в окне появится ссылка. Её также можно
скопировать из `.runtime/ngrok/public-url.txt`. Окно можно закрыть: туннель остаётся
работать в фоне. После перезагрузки запустите тот же файл вручную.

Для остановки общего доступа запустите **`stop-ngrok.cmd`**. Он завершает только
процесс ngrok, который запустил этот проект; Docker и данные остаются работать.
После остановки туннеля файл с последней ссылкой удаляется. Обычный локальный
режим можно вернуть запуском `start-docker.cmd`.

## На другом компьютере

Нужны Docker Desktop и ngrok. Установите ngrok по
[официальной инструкции для Windows](https://ngrok.com/download/windows), создайте
аккаунт и один раз выполните указанную в личном кабинете команду:

```powershell
ngrok config add-authtoken ВАШ_ТОКЕН
.\start-ngrok.cmd
```

Используйте собственный токен ngrok. Он сохраняется в профиле Windows
`%LOCALAPPDATA%\ngrok\ngrok.yml`, не копируется в проект и не отправляется в Git.
Токены Telegram на другом компьютере по-прежнему настраиваются отдельно через
локальный `.env.telegram.local`.

## Поведение и диагностика

- Компьютер, Docker и ngrok должны оставаться включёнными, с доступом в интернет.
- Бесплатный ngrok может показывать посетителям страницу подтверждения **Visit Site**;
  ограничения тарифа действуют на трафик сайта.
- Повторный запуск использует уже запущенный процесс этого проекта. После нового
  запуска ориентируйтесь на ссылку, которую скрипт вывел и сохранил после проверки.
- Если занят локальный порт инспектора, выберите другой:
  `start-ngrok.cmd -InspectorPort 4057`. Сначала остановите старый туннель.
- Сетевые ошибки и ошибки аккаунта смотрите в `.runtime/ngrok/stdout.log` и
  `.runtime/ngrok/stderr.log`. Не публикуйте конфигурацию с токеном.
- Если сборка или проверка не прошла, скрипт сообщает ошибку. Исправьте её и запустите
  файл повторно. Созданный туннель можно остановить через `stop-ngrok.cmd`.

Публично проксируется только frontend. Заказы и расписание проходят через его
существующие server routes к API. Публичные изображения из object storage выдаёт
`/media/...`: проверяются формат hash key и присутствие изображения в опубликованном
config/menu. Произвольные объекты не выдаются; redirects запрещены. База данных,
MinIO Console и API не получают отдельных туннелей. Host allowlist и доверие к
forwarded headers backend не расширяются.

`.env.ngrok.local` содержит вычисленные `PUBLIC_BASE_URL` и `ASSET_BASE_URL` и
используется только режимом `-PublicTunnel`. Он, журналы, PID процесса и ссылка
игнорируются Git. HTTP inspection ngrok отключён, локальный служебный API слушает
только `127.0.0.1`. Запуск при входе в Windows не регистрируется.

Публичный адрес также передаётся frontend для canonical URL и Open Graph, чтобы
при отправке ссылки не использовался адрес из старого локального набора данных.
