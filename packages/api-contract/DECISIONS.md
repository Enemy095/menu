# Contract decisions

## OpenAPI as source of truth

- Public API uses OpenAPI 3.0.3 and the single namespace `/api/v1/public`.
- The deployment exposes one configuration, one current menu and one order flow.
- Request host validation belongs to ingress/security and never selects business data.
- No routing identifier is accepted in path, query, headers or request bodies.
- `Idempotency-Key` is a required UUID header and is not part of `CreateOrderRequest`.
- The backend validates the menu and calculates all prices; the request has no total field.
- External notification/POS destinations are server-side configuration and are never public DTO fields.
- Errors use one stable `ErrorResponse` envelope.

## Canonical operations

```text
GET  /api/v1/public/config
GET  /api/v1/public/menu
POST /api/v1/public/orders
```

The previous slug-prefixed draft contract was not released and had no production order
controller, so version 1 is corrected in place. If evidence of an external release appears,
integration stops until a versioning ADR defines a new namespace and retirement window.

## Order authority

- Items contain stable menu IDs, quantities and explicit modifier selections.
- `CreateOrderRequest` is a discriminated union: delivery requires an address, while
  preorder and pickup accept only the confirmed optional guest count.
- A requested fulfillment time is intentionally absent until the owner confirms that rule.
- `clientMenuVersion` detects a stale cart.
- `serverTotalMinor` in the response is authoritative.
- An identical idempotent replay returns the original result; a different payload returns
  `409 IDEMPOTENCY_CONFLICT`.

## Confirmed operational configuration

- Weekly opening hours are a typed seven-day schedule plus a localized display string.
- Delivery is enabled, requires an address and currently has no operational fee policy.
- Marketing delivery thresholds are not exposed as minimum-order or free-delivery rules.
- Public order limits match the legacy validators exactly.
- MVP reads publish `ETag` and resource-specific cache metadata but do not promise
  unsupported `If-None-Match`/`304` behavior.

## Client and server

- TypeScript client is generated by OpenAPI Generator with generator `typescript-fetch`.
- Generated TypeScript is committed as a deterministic build artifact and never edited manually.
- Spring MVC controllers and Java DTOs implement this contract; Java server stubs are not generated.
- Consumers change only after OpenAPI lint, tests, generation and generated-diff checks pass.
